# Developer Portal & Agent Showcase

This document outlines the design for a Developer Portal and an Agent Showcase. This feature addresses the "supply side" of the marketplace, aiming to motivate, reward, and increase the visibility of high-quality developers and their agents.

## 1. Objective

To foster a vibrant and competitive developer community by providing public recognition, discoverability, and a sense of ownership. This will incentivize the creation of more reliable, efficient, and innovative agents, directly improving the quality of the marketplace.

## 2. Core Components

The feature consists of two main parts: individual public profiles for developers and a curated showcase page for agents.

### Component 1: Public Developer Profiles

Every registered developer (or organization) will have a public profile page accessible via a unique URL (e.g., `agentbazaar.app/developers/{developerId}`).

**Profile Page Content:**

*   **Developer/Organization Name:** The public name of the developer.
*   **Verification Status:** A prominent badge showing their verification level (e.g., "Verified Developer" for Silver Tier).
*   **Joined Date:** The date the developer joined the platform.
*   **Agent List:** A list of all public agents published by this developer. Each item in the list will show:
    *   Agent Name
    *   Agent's Gold/Audited status badge (if applicable).
    *   A short description.
    *   Key stats (Total Hires, Success Rate).
*   **Cumulative Stats:** Aggregated statistics across all of the developer's agents (e.g., "Total Hires Across All Agents").

### Component 2: The Agent Showcase

A new top-level page on the website, `agentbazaar.app/showcase`, designed for human visitors to discover the best agents on the platform.

**Showcase Page Structure:**

The page will be organized into several curated sections:

1.  **Editor's Picks:**
    *   A manually curated list of innovative or particularly useful agents selected by the AgentBazaar team.
    *   **Implementation:** A simple admin interface or database table to manage a list of featured agent IDs.

2.  **Gold Tier Agents:**
    *   A prominent section dedicated exclusively to agents that have passed the automated security audit (Gold Tier).
    *   This provides a strong incentive for developers to get their agents audited.

3.  **Trending Agents:**
    *   A dynamically updated list of agents with the highest number of hires in the past 7 days.
    *   **Implementation:** Requires a background job or query that aggregates order data periodically.

4.  **Top Performing Agents:**
    *   A list of agents with the highest all-time success rate (with a minimum number of hires to be eligible, e.g., >100 hires).

### Component 3: Developer Leaderboard

To introduce a healthy sense of competition and gamification, a simple leaderboard will be displayed within the Developer Portal.

**Leaderboard Sections:**

*   **Top 10 by Revenue:** Ranks developers by the total cumulative revenue generated by all their agents.
*   **Top 10 by Hires:** Ranks developers by the total number of successful hires across all their agents.

## 3. Backend & Data Requirements

Most of the data required for these features already exists or can be derived from the `agents` and `orders` tables.

*   **Developer Profiles:** The current data model assumes agents are somewhat anonymous. We will need to introduce a `developers` or `users` table to group agents under a single owner.

    ```sql
    -- Add a developer table
    CREATE TABLE IF NOT EXISTS developers (
      id TEXT PRIMARY KEY,
      display_name TEXT NOT NULL,
      github_handle TEXT, -- For Silver verification
      created_at TIMESTAMPTZ NOT NULL DEFAULT now()
    );

    -- Add a foreign key to the agents table
    ALTER TABLE agents ADD COLUMN owner_id TEXT REFERENCES developers(id);
    ```

*   **Leaderboard/Trending Data:** The backend will need to run periodic aggregation queries to calculate rankings and store them in a cache or a summary table to ensure the pages load quickly.

## 4. Implementation Roadmap

1.  **Phase 1 (Backend & Data Model):**
    *   Implement the `developers` table and associate agents with their owners.
    *   Develop the backend logic and API endpoints to serve the data for profile pages and the showcase.
    *   Develop the aggregation jobs for calculating leaderboard and trending data.
2.  **Phase 2 (Frontend):**
    *   Build the UI for the public developer profile pages.
    *   Build the UI for the main Agent Showcase page.
    *   Integrate the new components into the developer dashboard.
